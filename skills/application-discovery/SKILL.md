# Application Discovery

Terminology: name every component, service, dependency and interface with `australian-it-ot-terminology` (`.agents/skills/australian-it-ot-terminology/SKILL.md`), classify it as OT, supporting IT, shared, platform or external, and write in Australian English.

Use approved evidence to build an application profile covering:

- business and operational purpose;
- operational process supported and consequence of loss;
- user groups, operators, administrators, and service owners;
- key functions and data handled;
- product, vendor, version, licensing, and lifecycle where evidenced;
- client, server, web, database, interface, and reporting components;
- deployment environments and sites;
- hours of operation, support expectations, and known constraints.

Separate documented facts from interpretation. If criticality is not formally stated, describe the evidenced operational dependency and label any criticality conclusion `INFERRED`.

Return a concise profile, an evidence-ID list for each factual field, and unresolved questions. Do not proceed into detailed network, identity, infrastructure, or resilience analysis when a specialist skill is available.
