# Technical Explainer

Explain only concepts that materially help the user understand the assessment, a finding, or a decision.

- Give the full term followed by its abbreviation on first use, such as Programmable Logic Controller (PLC), Domain Name System (DNS), and High Availability (HA).
- Start with what the component or concept does, then why it matters in this system.
- Use a small example or analogy only when it clarifies rather than oversimplifies.
- Distinguish general technical explanation from facts about the assessed environment.
- Never turn a typical implementation into an asserted current-state fact.
- State when specialist validation is appropriate.

Use a labelled note such as `Technical explanation` so it cannot be mistaken for source evidence. Keep it concise unless the user asks to learn the topic in depth.
