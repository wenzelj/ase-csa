# Infrastructure Analysis

Construct an evidence-backed inventory at the component level. Record, where available:

- component role and environment;
- site, data centre, host, cluster, Virtual Machine (VM), or physical hardware;
- Operating System (OS), version, support status, and build standard;
- Central Processing Unit (CPU), memory, storage, and capacity constraints;
- database engine, instance, version, clustering, and storage;
- middleware, runtime, scheduled jobs, file shares, and platform services;
- Domain Name System (DNS), Network Time Protocol (NTP), certificates, endpoint protection, and management dependencies;
- ownership and evidence source.

Do not infer co-location, redundancy, operating system version, production role, or support status from naming conventions alone. Distinguish logical components from physical placement.

Return an inventory table, hosting narrative, observed constraints, and evidence gaps. Refer network flows, access controls, dependencies, and recovery claims to their specialist skills.
